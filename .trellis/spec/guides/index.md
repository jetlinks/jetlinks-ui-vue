# 思考指南（Thinking Guides）

> **目标**：在编码前把“容易漏想的点”提前想清楚。

---

## 为什么需要思考指南？

多数线上问题不是“不会写代码”，而是“当时没想到”：

- 没想到层间边界 → 跨层 Bug
- 没想到复用机会 → 大量重复代码
- 没想到边界输入 → 运行时异常
- 没想到后续维护 → 可读性差、迭代慢

这些指南用于帮助你在实现前问对问题。

## 快速触发器（什么时候该读指南）

### 何时读“跨层思考”

- [ ] 功能涉及 3 层及以上（API / Store / Component / DB 契约）
- [ ] 数据在不同层发生格式转换
- [ ] 不确定某段逻辑应放在哪一层
- [ ] 同一数据被多个消费者依赖

→ 读 `cross-layer-thinking-guide.md`

### 何时读“代码复用思考”

- [ ] 你正在写“和已有代码很像”的逻辑
- [ ] 相同模式在仓库里出现 3 次以上
- [ ] 改一个常量需要修改很多文件
- [ ] 正在新增工具函数/公共方法

→ 读 `code-reuse-thinking-guide.md`

### 何时读“跨平台思考”

- [ ] 编写会被不同系统执行的脚本
- [ ] 处理路径、换行、编码、shell 命令
- [ ] 在 README/文档中写执行示例
- [ ] 从 shell 脚本迁移到 Python 脚本

→ 读 `cross-platform-thinking-guide.md`

## 关键规则：修改前先检索

> **改任何值之前，先全局搜索一次。**

```bash
grep -r "value_to_change" .
```

这一个动作能避免大量“只改了一半”的遗漏问题。

---

## 使用建议

1. 编码前：先读相关指南（1~3 分钟即可）
2. 编码中：遇到复杂/重复问题再回看清单
3. 复盘后：把新经验沉淀进相应指南

---

**核心原则**：多花 20 分钟思考，省下 2~3 小时排错。
