# 跨层思考指南

> **目标**：实现前先把跨层数据流和边界契约梳理清楚。

---

## 问题本质

大部分复杂 Bug 发生在“层与层之间”，而不是单层内部。

常见跨层问题：

- API 返回结构 A，前端按结构 B 解析
- 中间层转换时字段丢失或语义变化
- 不同层重复实现同一规则，最终不一致

---

## 跨层功能实现前步骤

### Step 1：画出数据流

```text
输入源 → 转换 → 存储/传输 → 读取 → 转换 → 展示
```

对每个箭头都问：

- 当前数据格式是什么？
- 在这一步最可能出什么错？
- 校验与兜底由谁负责？

### Step 2：识别边界点

| 边界 | 常见风险 |
|------|----------|
| API ↔ Store/Service | 字段缺失、类型不匹配 |
| Service ↔ 数据源 | 空值处理、格式转换 |
| Backend ↔ Frontend | 序列化、时间格式、枚举值 |
| Component ↔ Component | props 结构漂移 |

### Step 3：定义契约

每个边界至少明确：

- 输入格式（字段、类型、可空性）
- 输出格式（字段、类型、默认值）
- 错误分支（错误码、提示、重试策略）

---

## 常见跨层反模式

### 反模式 1：隐式格式假设

- ❌ “默认后端永远是这个格式”
- ✅ 在边界处显式转换与兼容

### 反模式 2：分散校验

- ❌ 多层各自校验同一规则，且标准不一致
- ✅ 在入口层统一校验，下游只消费标准化数据

### 反模式 3：抽象泄漏

- ❌ 上层组件感知底层存储细节
- ✅ 每层只依赖相邻层公开契约

## 跨层功能检查清单

实现前：

- [ ] 已画完整数据流
- [ ] 已识别关键边界点
- [ ] 已定义每个边界契约
- [ ] 已确定校验责任归属

实现后：

- [ ] 已覆盖空值/非法值/边界值
- [ ] 已验证错误路径与提示
- [ ] 已验证数据往返不丢失

---

## 何时需要单独写流程文档？

建议补充详细流程文档的场景：

- 涉及 3 层及以上
- 多人/多团队协作
- 数据结构复杂且易变
- 历史上在该链路反复出问题
